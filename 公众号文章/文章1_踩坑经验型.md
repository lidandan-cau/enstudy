背单词这件事，我失败过太多次了。

背了忘，忘了背，循环往复，怀疑人生。

某天突然想到一个思路：**如果单词是藏在一篇有意思的故事里呢？**

我去找了找，没找到合适的工具——要么故事太枯燥，要么词汇不是我要考的。

那就自己做一个。

用了两个多周，做出来了，叫 **AI短文记单词**。期间踩了不少坑，今天全说出来。

---

## 最大的坑：让 AI 生成「格式化内容」

这个小程序的核心，是让 AI 生成一篇短故事，故事里的生词要用特定格式标注，比如：

```
The [knight|/naɪt/|骑士] rode through the dark forest.
```

括号里是：英文单词 | 音标 | 中文意思。

听起来简单，但让 AI 稳定地生成这个格式，花了我相当多时间。

第一次我只说：「生成一篇包含10个生词的英文故事，生词要标注音标和中文。」

AI 给的格式五花八门——有的用括号，有的用星号，有的直接在故事后面加词汇表，每次都不一样，没法解析。

后来我把格式写得非常死：

> 「每个生词必须用 `[英文单词|音标|中文意思]` 格式嵌入句子，不允许有其他标注方式，不在文章末尾添加词汇表。示例：The [ancient|/ˈeɪnʃənt/|古老的] temple stood on the hill.」

加了「示例」之后，AI 的格式稳定性提升了很多。

**教训：让 AI 生成结构化内容，一定要给示例，光说格式描述是不够的。**

---

## 第二个坑：云函数调用 AI 接口，总是超时

小程序前端不能直接调用第三方 AI 接口，得用**微信云函数**做中转。

第一版写好，本地测试没问题，部署到云端就开始报超时。

AI 生成一篇故事大概需要 10-15 秒，而微信云函数默认超时是 3 秒。

去查了文档，云函数可以在 `config.json` 里设置超时时间，最长60秒。改成 `"timeout": 60` 就解决了。

但还有一个问题：AI 生成故事期间，用户界面没有反馈，用户以为卡死了。

我加了一个「生成中」的 loading 动画，三个点来回跳，用户立刻不焦虑了。

## 第三个坑：生词去重的逻辑

小程序里有个功能：**每次生成新故事时，已经出现过的单词不能再出现**，保证用户每次都在学新词。

第一版实现太简单，只排除了当前文章的词，换一篇新文章时又出现了旧词。

后来改成：每次生成时，把本地存储里所有文章的所有单词都取出来，传给云函数，让 AI 生成时排除这些词：

```javascript
// 读取所有已用过的词
const list = wx.getStorageSync('enstudy_articles') || []
const seen = new Set()
list.forEach(a => (a.words || []).forEach(w => seen.add(w.toLowerCase())))
const usedWords = [...seen]
// 传给云函数
wx.cloud.callFunction({
  name: 'generateStory',
  data: { ..., usedWords }
})
```

加了这个逻辑之后，每篇故事里的词都是用户真正没见过的，学习效率高多了。

## 第四个坑：复习算法怎么设计

做复习功能时，我想做一个「知道/不知道」的卡片翻转复习，并且要记录用户对每个词的掌握程度。

但「掌握」怎么定义？

我定的规则是：**同一个词，点过2次「认识」且「认识次数 > 不认识次数」，才算掌握。**

```javascript
function isMastered(entry) {
  return entry && entry.known >= 2 && entry.known > entry.unknown
}
```

这个规则不复杂，但设计的时候想了挺久——太容易掌握，没有意义；太难达到，用户会放弃。

## 第五个坑：故事风格和词书要分开选

第一版把「风格」和「词书」混在一起，用户选完词书，风格就固定了。

测试发现，用户其实希望能自由组合——**KET词书 + 玄幻修仙风格**，这样背单词会有一种奇特的快乐。

拆开来设计之后，可以选5种词书（KET/PET/四级/六级/考研）× 6种风格（玄幻/都市/科幻/历史/童话/悬疑），理论上30种组合，每次都不一样。

## 做完了是什么感觉

**AI短文记单词**现在的功能：
- AI 实时生成故事，包含对应词书生词
- 阅读页支持3种显示模式：中英双语 / 仅英文 / 仅中文
- 点击生词可以看音标和中文释义
- 复习页：翻卡片，标记认识/不认识
- 掌握度追踪：新词 / 待加强 / 已掌握 三分类
